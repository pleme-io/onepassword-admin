# What opadmin cannot reach

Generated by the kinko bidama (blue). Do not edit by hand.

| Concern | Why | What would have to exist |
|---|---|---|
| users | no API a reconciler can hold: the SDK has none, SCIM is Business-only with a deprecated bridge, op needs a human session | a user API on the SDK or Connect |
| groups | the SDK reads groups only; create, rename and delete need op or SCIM | group CRUD on the SDK |
| group membership | membership changes need op or SCIM | membership on the SDK |
| built-in vaults | a service account never reaches Personal, Private, Employee or the default Shared vault | none: a vendor rule |
| vaults the service account did not create | a service account updates, deletes and grants only on vaults it created; its access is immutable | adoption of an existing vault by a service account |
| account policy | sign-in, firewall, 2FA, recovery, roles and billing have no API on any surface | an account settings API |
| allow_admins_access read-back | the SDK's Vault carries no such field, so the provider keeps the value it wrote | the field on Vault |
